# Mobile App for Online Assessment — K–12 EdTech

**Role:** Product Manager  
**Date:** 2024 (as shown in portfolio source)  
**Audience:** K–12 schools  
**Focus:** EdTech and mobile assessment  
**Status:** Shipped (as shown in portfolio source)

## 1. Product overview

The Mobile App for Online Assessment was developed to extend online assessment management from the web platform to mobile devices.

The app was intended to help educators and administrators upload assessment materials, organize tests by class or subject and track student progress from their phones.

## 2. The problem

The source portfolio identifies the core challenge as bringing online assessment management from web to mobile and achieving web-to-mobile parity.

A desktop workflow does not automatically translate well to a phone. Users may need to complete important school activities away from a computer, and a mobile experience that lacks key capabilities can force them to switch back to the web platform.

**Product problem statement:** How might we give school users access to essential online assessment workflows on mobile while preserving the core capabilities and clarity of the web experience?

## 3. Discovery and problem framing

The source portfolio confirms collaboration with engineering, design and school operations teams and describes my role in leading discovery and delivery of mobile features.

It does not document specific interviews, usability tests, school sample sizes, analytics or the exact web-to-mobile gap analysis. The following is a reconstruction of the discovery questions the product problem calls for, rather than a claim that each method was used.

A strong discovery narrative for this project should cover:

- **User and task understanding:** which assessment tasks educators and administrators need to complete on mobile.
- **Web experience review:** which existing web workflows were essential to carry over and which needed adaptation.
- **Context of use:** where and when school users need mobile access, and what constraints affect completing tasks on a phone.
- **Workflow prioritization:** which actions are critical for the first useful mobile release.
- **Parity definition:** how the team determined whether the mobile app covered the core user needs without simply copying every desktop screen.

The central product insight was that mobile parity should be defined around essential user tasks, not visual duplication of the web interface.

## 4. Product decisions and rationale

The source portfolio confirms the following scope:

- **Bring core assessment activities to mobile:** support uploading assessment materials, organizing tests by class or subject and tracking student progress.
- **Prioritize mobile-first usability:** make core desktop capabilities accessible through a phone-friendly experience.
- **Work across product and school operations:** collaborate with engineering, design and school operations to shape delivery.
- **Balance parity with clarity and speed:** preserve essential functionality without sacrificing the usability expected on mobile.

### Trade-offs to explain in an interview

These are product tensions implied by the goal of web-to-mobile parity. Validate which were actual decisions:

- **Feature parity versus usability:** copying every web feature may create a crowded mobile interface. Prioritizing essential tasks can make the app easier to use but may leave some workflows web-only.
- **Consistency versus platform conventions:** familiar workflows help existing users, while mobile-specific interaction patterns can make tasks easier on smaller screens.
- **Upload capability versus device constraints:** assessment material handling may be affected by device storage, connectivity and file-selection experience. Explain how the team handled these constraints only if this was part of the actual scope.
- **Speed to market versus completeness:** shipping the highest-value workflows first can provide earlier value, but requires clear communication about what remains available only on web.

## 6. Outcomes and impact

**Delivered:** a mobile app for online assessment, described in the source portfolio as shipped. It extended core assessment-management capabilities to mobile and aimed to provide web-to-mobile parity.

**Intended value:** reduce friction in assessment administration, improve access for school users and provide visibility into student performance from mobile devices.

**What is not yet quantified:** the source does not include adoption, task-completion, assessment-upload success, time-saving, usability or learning-outcome metrics. Claims that the app saved schools time or improved student performance should be supported by evidence before being presented as measured results.

### Metrics I would use to evaluate the product

- Mobile app activation and monthly active school users.
- Percentage of assessment workflows completed on mobile.
- Assessment upload success and failure rates.
- Time to complete key tasks, such as creating or organizing an assessment.
- Task abandonment and error rates by workflow.
- Repeat usage by educators and administrators.
- Support requests related to assessment setup and mobile usability.
- User satisfaction and usability feedback.
- Mobile-versus-web completion rates for equivalent tasks.
